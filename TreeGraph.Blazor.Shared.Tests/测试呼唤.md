用户在询问以后如何让我（AI 助手）添加新测试。这是一个使用方式的问题，不需要写代码。我应该简洁地说明触发方式和模板。

关键点：
1. 用户如何"呼唤"我添加测试
2. 应该提供什么信息让我高效工作
3. 给一个可复用的提问模板

让我直接回答，不需要工具调用。
不需要特殊"呼唤"——直接用自然语言描述需求即可。以下是几种典型句式，我都能识别并执行：

## 触发模板

### 1. 直接说要测什么
```
给 X 加个测试，验证 Y 场景下 Z 行为
```
例：`给 StringTreeDemoSeeder 加个测试，验证删除 Space 时级联清理 EAV`

### 2. 复用现有测试风格
```
按 StringTreeDemoSeederTests 的风格，加一个测试：……
```

### 3. 给我测试意图（最简形式）
```
测试 demo-space-002 的 priority 选项值不被 demo-space-001 的查询误返
```

## 我会自动做的事

每次加测试，我会按现有模式自动处理：
1. 在 `TreeGraph.Api.Tests/Tests/StringTreeDemoSeederTests.cs` 末尾追加方法（不新建文件）
2. 用 `[Fact]` + `async Task` + `IntegrationTestBase` 的 `EavApiFactory` fixture
3. DB 白盒 + API 黑盒两种风格择一或并用
4. 测试方法上方加注释块（编号 + 维度说明）
5. 编译 + 运行验证全绿

## 高效提问的小贴士

为了让一次到位，**告诉我**：
- **测什么对象**（seeder / controller / service）
- **关注的行为**（创建 / 隔离 / 级联 / 边界值）
- **预期结果**（独立 / 互不干扰 / 抛错 / 返回 N 条）

**不必告诉我**（我自己查）：
- 文件路径、命名空间、fixture 用法
- MudBlazor/xUnit API 细节
- 已有测试的编号

## 失败重试机制

如果新测试运行失败（如我数错行数、字段名打错），我会：
1. 读失败堆栈
2. 修测试断言或 seeder 数据
3. 重跑直到全绿
4. 同步更新 seeder 顶部注释中的对比矩阵

直接说"加测试：……"即可，我会从那里接手。
