以下是为 `ElasticController` 接入**两阶段重排序**的完整代码示例。  
它先通过 KNN 召回候选集（第一阶段），再使用一个更精确的模型（第二阶段）对候选重新打分排序，最终返回精排后的结果。

---

## 1. 定义重排序服务接口

```csharp
// IRerankService.cs
using ElasticsearchService.Models;

public interface IRerankService
{
    /// <summary>
    /// 对候选文档列表进行重排序
    /// </summary>
    /// <param name="query">原始查询文本</param>
    /// <param name="documents">第一阶段召回的文档列表</param>
    /// <param name="topN">最终需要返回的数量</param>
    /// <returns>按相关性降序排列的文档列表（只返回前 topN 个）</returns>
    Task<List<ElasticQuestion>> RerankAsync(string query, List<ElasticQuestion> documents, int topN);
}
```

## 2. 实现一个基于规则的轻量级重排序（示例）

这里演示一个**基于查询词在标题/内容中匹配密度**的简单评分，实际生产可替换为 Cross-Encoder 模型或 API。

```csharp
// SimpleRerankService.cs
using System.Text.RegularExpressions;
using ElasticsearchService.Models;

public class SimpleRerankService : IRerankService
{
    public Task<List<ElasticQuestion>> RerankAsync(string query, List<ElasticQuestion> documents, int topN)
    {
        if (documents.Count == 0) return Task.FromResult(new List<ElasticQuestion>());

        // 分词（按空白和标点拆分）
        var queryTerms = Regex.Split(query.ToLower(), @"\W+").Where(t => t.Length > 1).ToList();
        if (!queryTerms.Any()) return Task.FromResult(documents.Take(topN).ToList());

        // 计算每个文档的得分：标题匹配权重 3，内容匹配权重 1
        var scored = documents.Select(doc =>
        {
            var titleText = (doc.Title ?? "").ToLower();
            var contentText = (doc.Content ?? "").ToLower();

            int titleHit = queryTerms.Count(term => titleText.Contains(term));
            int contentHit = queryTerms.Count(term => contentText.Contains(term));

            double score = titleHit * 3.0 + contentHit * 1.0;
            return (doc, score);
        })
        .OrderByDescending(x => x.score)
        .Take(topN)
        .Select(x => x.doc)
        .ToList();

        return Task.FromResult(scored);
    }
}
```

## 3. 修改 `ElasticController`，集成两阶段重排序

重点改动：
- 注入 `IRerankService`。
- 第一阶段 KNN 搜索时增大 `K`（召回更多候选）。
- 第二阶段调用重排序服务，截取最终 `size` 个结果。

```csharp
// ElasticController.cs 修改后的完整代码
using System.Text.RegularExpressions;
using Elastic.Clients.Elasticsearch;
using Elastic.Clients.Elasticsearch.QueryDsl;
using ElasticsearchService.Embeds;
using ElasticsearchService.Models;
using Microsoft.AspNetCore.Mvc;

namespace ElasticsearchService.Controllers;

[ApiController]
[Route("[controller]")]
public class ElasticController : ControllerBase
{
    private readonly ElasticsearchClient _client;
    private readonly IEmbeddingService _embeddingService;
    private readonly IRerankService _rerankService;

    // 构造函数增加 IRerankService
    public ElasticController(
        ElasticsearchClient client,
        IEmbeddingService embeddingService,
        IRerankService rerankService)
    {
        _client = client;
        _embeddingService = embeddingService;
        _rerankService = rerankService;
    }

    // 原有 Search / SimilarTitles 保持不变...

    [HttpGet("semantic")]
    public async Task<IActionResult> SemanticSearch(
        [FromQuery] string query,
        [FromQuery] int size = 10,
        [FromQuery] int recallSize = 100)   // 第一阶段召回数量（可调）
    {
        if (string.IsNullOrWhiteSpace(query))
            return BadRequest("查询词不能为空");

        // 1. 生成查询向量
        var queryEmbedding = await _embeddingService.GenerateEmbeddingAsync(query);

        // 2. 第一阶段：KNN 召回更多候选（recallSize）
        var searchRequest = new SearchRequest<ElasticQuestion>("questions")
        {
            Size = recallSize,   // 召回 recallSize 个
            Knn = new[]
            {
                new KnnSearch
                {
                    Field = "embedding",
                    QueryVector = queryEmbedding,
                    K = recallSize,               // 与 Size 一致
                    NumCandidates = recallSize * 2 // 可调
                }
            }
        };

        try
        {
            var response = await _client.SearchAsync<ElasticQuestion>(searchRequest);
            if (!response.IsValidResponse)
                return Problem("语义搜索第一阶段失败", response.DebugInformation);

            var candidates = response.Documents.ToList();

            // 3. 第二阶段：重排序（精排）
            var reranked = await _rerankService.RerankAsync(query, candidates, size);

            return Ok(reranked);
        }
        catch (Exception ex)
        {
            return Problem("语义搜索异常", ex.Message);
        }
    }
}
```

## 5. （可选）使用外部重排序 API（如 Cohere）

若需接入 Cohere Rerank API，可创建 `CohereRerankService`：

```csharp
public class CohereRerankService : IRerankService
{
    private readonly HttpClient _httpClient;
    private readonly string _apiKey;

    public CohereRerankService(HttpClient httpClient, IConfiguration config)
    {
        _httpClient = httpClient;
        _apiKey = config["Cohere:ApiKey"];
    }

    public async Task<List<ElasticQuestion>> RerankAsync(string query, List<ElasticQuestion> documents, int topN)
    {
        if (documents.Count == 0) return new List<ElasticQuestion>();

        // 构造请求体（Cohere 格式）
        var request = new
        {
            model = "rerank-english-v2.0",
            query = query,
            documents = documents.Select(d => new { text = $"{d.Title}\n{d.Content}" }).ToList(),
            top_n = topN
        };

        var response = await _httpClient.PostAsJsonAsync("https://api.cohere.ai/v1/rerank", request);
        response.EnsureSuccessStatusCode();

        var result = await response.Content.ReadFromJsonAsync<CohereRerankResponse>();
        // 根据 result.Results 中的索引重新排序
        var orderedDocs = result.Results
            .OrderBy(r => r.Index)
            .Select(r => documents[r.Index])
            .ToList();

        return orderedDocs;
    }
}

// 简单响应模型（略）
```

然后注册：
```csharp
builder.Services.AddHttpClient<CohereRerankService>();
builder.Services.AddSingleton<IRerankService, CohereRerankService>();
```

---

## 7. 参数调优建议

- **`recallSize`**：一般为最终返回 `size` 的 5~10 倍，但不宜过大，否则重排序耗时增加。
- **`NumCandidates`**：在 KNN 中可设为 `recallSize * 2` 或更多，保证召回质量。
- **重排序模型**：若使用 Cross-Encoder，效果最好；基于规则的简单重排序虽轻量，但提升有限，建议升级为真正的语义重排序模型。

---

## 8. 注意事项

- 若索引数据量很大，`recallSize` 需根据集群性能权衡。
- 重排序服务应具备**高性能**，否则会拖慢整体响应。可考虑异步或缓存。
- 如果使用外部 API，务必处理超时和重试机制。

以上代码可**直接复制**并修改，根据你的实际重排序模型填充 `IRerankService` 的实现即可。
