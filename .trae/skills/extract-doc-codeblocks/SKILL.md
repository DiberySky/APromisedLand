# 提取设计文档代码块并落盘

把"长文本设计文档 → 项目文件"的机械映射固化为单条命令。文档是唯一事实源，提取过程**字节级保真**，禁止任何智能改写。

## 触发场景

用户消息中给出一个 `.txt` 文档路径（通常在
`C:\Users\_Dibery_\AppData\Roaming\Trae CN\User\workspaceStorage\...\long-text\<session-id>\<doc-id>\`
下，文件名常以 `#` 开头并含空格），并要求"替换现有文件/按文档实施/补齐"。

## 执行步骤

### 1. 解析真实文档路径

- 用户消息常带拼接伪前缀，形如 `d:\APromisedLand/c:\Users\...\# xxx.txt`。
  真实路径是 `c:\Users\...` 部分，剥掉工作区前缀。
- 路径含 `#` 与空格时不要靠猜；用引号包裹，或先用 `Get-ChildItem <目录>` 解析出
  `FullName` 再使用。
- 先列出文档章节标题，确认文件清单与数量：

  ```powershell
  $p = (Get-ChildItem "<文档所在目录>").FullName
  Select-String -Path $p -Pattern "^#{1,4} " -Encoding UTF8
  ```

### 2. 通读文档，区分"整文件替换"与"补丁追加"

- 章节形如 `## 文件 N / M：\`项目相对路径\``，标题后紧跟一个 ```` ```language ````
  fenced 块的，是**整文件替换**——用脚本提取。
- 文档若明确写"在 XXX 区域追加/仅补丁/不要整文件覆盖"（常见于
  `EavApiClient.cs` 这类只新增方法的文件），**跳过脚本提取**，改用 Edit 工具
  以当前文件真实片段为锚点精确插入。
- 文档末尾的"需你确认/下一步/已知未做"章节不属于代码文件，不提取。

### 3. 运行提取脚本

脚本位于本技能目录 `scripts/extract_codeblocks.py`，接受序号白名单：

```powershell
# 先 dry-run 核对清单、字节数、围栏语言
python "<技能目录>\scripts\extract_codeblocks.py" "<文档路径>" --root "d:\APromisedLand" --dry-run

# 正式落盘（可只提取整文件替换的序号，如 1,2,4；3 号为补丁则不列入）
python "<技能目录>\scripts\extract_codeblocks.py" "<文档路径>" --root "d:\APromisedLand" --only 1,2,4
```

要求：

- 每个文件必须输出 `[OK]`（写入后已自动读回字节比对）。出现 `[MISMATCH]`
  必须停止排查，不得继续宣称完成。
- 脚本只提取每个章节的**第一个** fenced 块。若章节结构异常（多块、无块、
  `[WARN]`），停下来人工读文档判断，不要自行选块。

### 4. 补丁文件手工处理

对第 2 步标记为补丁的文件：先 Read 目标区域当前真实内容 → 用最小稳定锚点
Edit 插入 → 不改写周边代码。

### 5. 编译验证与偏离记录

- 提取/补丁完成后，对受影响项目运行 `dotnet build -v q`，必须 0 错误。
- 文档代码若因当前项目真实 API 差异编译失败（如泛型参数类型错误、旧版组件 API、
  不存在的类型名），以**仓库真实定义为准**做最小修正，并在最终报告中逐条列出
  "与文档的偏差及原因"。不得默默改写。
- 验证文档声称的关键修复点真实存在（Grep 抽查 1~3 个标志性符号），不只看编译。

### 6. 报告

用表格列出：文件、方式（逐字覆盖/补丁/修正）、字节与行数（脚本已输出）、
编译结果、是否涉及数据库迁移；补丁与修正单独说明。

## 保真红线

- 不合并换行、不清理标记、不规范化标点/引号/空格、不"顺手优化"文档代码。
- 不在仓库里留下一次性临时脚本——脚本已固化在本技能 `scripts/` 中，直接复用。
- 数据库迁移类操作不自动执行；模型有变更时生成迁移命令交用户手动执行。
